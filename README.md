# Search Engine

Учебный консольный поисковый движок на C++. Программа индексирует локальные текстовые документы, обрабатывает запросы из JSON и сохраняет ранжированные результаты в `answers.json`.

## Возможности

- построение инвертированного индекса по текстовым файлам;
- поиск документов, содержащих хотя бы одно слово запроса;
- расчёт абсолютной и относительной релевантности;
- сортировка результатов по убыванию релевантности;
- ограничение количества ответов через `max_responses`;
- чтение конфигурации, документов и запросов без ручного ввода;
- модульные тесты индексирования и поиска на Google Test.

## Технологии

- C++17;
- CMake 3.20 или новее;
- [nlohmann/json](https://github.com/nlohmann/json) для работы с JSON;
- [Google Test](https://github.com/google/googletest) для тестов.

Зависимости загружаются через CMake `FetchContent`, поэтому при первой сборке нужен доступ к GitHub.

## Сборка

```bash
git clone https://github.com/Kratos31071992/Search-engine.git
cd Search-engine/search_engine
cmake -S . -B build
cmake --build build
```

При использовании CMake 4.x старые версии зависимостей могут потребовать явно разрешить устаревшие политики:

```bash
cmake -S . -B build -DCMAKE_POLICY_VERSION_MINIMUM=3.5
cmake --build build
```

## Запуск

Конфигурационные файлы копируются в каталог сборки, поэтому программу нужно запускать из `build/src`:

```bash
cd build/src
./search_engine
```

После запуска результат появится в файле `build/src/answers.json`.

В Windows имя и расположение исполняемого файла зависят от генератора CMake, например: `build\src\Debug\search_engine.exe`.

## Настройка документов и запросов

### `config/config.json`

```json
{
  "config": {
    "name": "SkillboxSearchEngine",
    "version": "0.1",
    "max_responses": 5
  },
  "files": [
    "resource/file001.txt",
    "resource/file002.txt",
    "resource/file003.txt"
  ]
}
```

- `files` — список индексируемых текстовых файлов;
- `max_responses` — максимальное число документов в ответе на один запрос;
- `version` должен быть равен `0.1`.

### `config/requests.json`

```json
{
  "requests": [
    "milk water",
    "capital",
    "non existing word"
  ]
}
```

Каждый запрос содержит одно или несколько слов. В выдачу попадают документы, в которых встречается хотя бы одно уникальное слово запроса. Документы с большей суммарной частотой слов получают более высокую релевантность.

## Тесты

```bash
cd Search-engine/search_engine
ctest --test-dir build/tests --output-on-failure
```

Также можно напрямую запустить исполняемый файл `server_test` из каталога `build/tests`.

## Как рассчитывается релевантность

Для каждого подходящего документа суммируется частота всех слов запроса. Затем полученная абсолютная релевантность делится на максимальную абсолютную релевантность среди документов, найденных по этому запросу. Поэтому относительная релевантность лучшего документа равна `1.0`, а остальные получают значения от `0.0` до `1.0`.
